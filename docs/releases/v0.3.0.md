# v0.3.0 — Turkish indexed discovery

This candidate completes the implementation and documentation of the OpenSearch
milestone (#29, epic #24). It requires Python **3.12+** and exposes **nine MCP
tools**. Publication is pending the reviewed topic → `develop` → `master`
promotion, annotated tag and release assets described in the
[release checklist](../RELEASE_0.3.0.md).

## Highlights

- Optional Turkish indexed discovery through `search_tuik` and
  `search_tuik_datasets`: case/ASCII handling, inflections, apostrophes,
  abbreviations, synonyms and bounded typo tolerance. General search adds
  kind/theme/date/downloadability filters, scores, highlights, facets and
  indexing/source timestamps.
- A paced metadata crawler and `tuik-mcp-index` build versioned indices with
  count verification and atomic alias swaps; incremental refreshes preserve
  state on failure. Bounded alternate listing modes handle overlapping official
  portal pages without accepting an incomplete or changing corpus.
- Reproducible five-system evaluation on **3,424 frozen metadata documents**,
  **48 queries** and **1,390 AI-reviewed pairs**, retaining source evidence,
  judgments and revision reasons. Real OpenSearch integration runs in CI.
- Already merged follow-ups ship in this tag: opt-in table/PDF passage indexing
  (`--content`, `--content-file`), best-effort PDF tables and the new
  `chart_tuik_data` PNG line/bar tool. Content indexing is optional and is outside
  the metadata relevance experiment; chart rendering requires the `viz` extra.

## Installation and upgrade

After the tag is published, install its source or a wheel from the GitHub release:

```bash
python -m pip install 'git+https://github.com/ByRock010/TUIK-Data-MCP-Server.git@v0.3.0'
# Include optional PNG charts:
python -m pip install 'tuik-mcp[viz] @ git+https://github.com/ByRock010/TUIK-Data-MCP-Server.git@v0.3.0'
tuik-mcp
```

For a checkout, use `python -m pip install -e '.[dev,viz]'`. This process does not
publish to PyPI. OpenSearch is optional; the server/indexer use HTTP directly and
do not require the optional `search` client extra. Existing file-reading, typed
query and snapshot-bound cursor calls remain supported.

Follow the [README setup](../../README.md#local-opensearch-development-stack)
for Docker Compose, environment variables and indexing. Export the settings into
the MCP server process; `.env` is not loaded by Python. The local stack pins
OpenSearch **3.3.2** and keeps its insecure development ports on loopback.

**Rebuild an existing index once:** mapping schema **2** adds page/sheet locators.
Run `tuik-mcp-index --full --listing-attempts 2 --alternate-listing-mode` before
incremental refreshes of an older schema. Keep the existing crawl/content state
files; a full rebuild retains cached opt-in file content. The old physical index
is retained for rollback. Do not replace the served alias with a concrete index.

## Measured behavior and limits

The [full comparison](../verification/issue-20-full-corpus-2026-11-05.md) retains
`multi_field_synonyms`: among the three same-corpus OpenSearch variants it has
the best nDCG@10 (**0.7304**) and pooled Recall@10 (**0.4296**). Built-in Turkish
has better MRR@10 (**0.9075**, versus **0.8796**). Portal/literal scores use
different eligible corpora and cannot establish a same-corpus ranking advantage.

These are one dependent AI assessor's grades with a sequential source review
under [ADR 0004](../adr/0004-ai-relevance-evaluation.md). Independent human
validation was not performed; κ is not applicable. Pooled recall is not exhaustive
recall, and conceptual relevance does not guarantee a currently downloadable
table or a direct answer to every geographic/semantic question. The standalone
AI report's `release_gate_satisfied:false` does not certify publication.

Without a configured/reachable index, datasets fall back to literal matching and
general discovery to the live portal, with explicit warnings and unsupported
filter/facet limitations. `live=true` explicitly queries the portal. Indexed
acceptance rejects fallback. Tables, publications and archives are not part of
the frozen metadata corpus; opt-in content coverage is bounded by download and
parse budgets. No embeddings, hybrid retrieval, OCR or canonical database ships.

See the [candidate verification](../VERIFICATION.md) for dated real MCP, live
upstream, cluster, offline and clean-distribution results. Those checks establish
the candidate's behavior; the release exists only after protected promotion and
tag publication.
