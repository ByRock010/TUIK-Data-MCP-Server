## Method and evidence

One Codex session assigned 0–2 relevance grades to all **917 query–document
pairs**, covering **351 distinct documents** and **48 frozen queries**. The pool
is the union of the historical portal/literal baseline and all three committed
OpenSearch pilot runs. The human fixture's **545** original pairs remain blank.
No `judge_a`, `judge_b`, human identity or adjudication was manufactured.

Assessment used identity-ordered titles, resource types and stored descriptions,
with selected ambiguous descriptions inspected. Titles were reviewed across all
48 queries. Source pages, exported rows, PDF contents and actual geographic or
age/sex dimension values were not fetched. A generic `Coğrafi Kapsam` field was
not treated as proof of a requested province's availability. This metadata-only
scope is an explicit limitation; even a grade 2 is not verified row availability.

The assessor also worked on the scorer and had prior knowledge of system designs.
Identity ordering hides rank/system columns in the review view but does not make
this an independent blind experiment. There is **one AI assessor**, **zero human
judge pairs**, and **no defined Cohen's κ**. Human judges should receive blank
forms without seeing these labels or scores, to avoid anchoring their decisions.

- [Individual grades and per-query rationale](search-ai-assessment-2026-11-04.json):
  **383 grade 2**, **336 grade 1**, **198 grade 0**; source run hashes and the
  pooled query/document/evidence fingerprint are retained.
- [Machine-readable metric report](search-ai-scores-2026-11-04.json):
  `status: ai_preliminary`, `release_gate_satisfied: false`, overall/category/type
  metrics, zero unjudged share, and explicit scope/assessor limitations.
- [Portal/literal collection](search-baseline-2026-10-26.json) and

## Reproduce and hand off

From the repository root, with the development environment installed:

```bash
.venv/bin/python scripts/evaluate_search.py pool \
  --runs docs/verification/search-baseline-2026-10-26.json \
    docs/verification/search-variants-dataflows-2026-11-03.json \
  --output /tmp/pooled.json
.venv/bin/python scripts/evaluate_search.py score-ai \
  --suite /tmp/pooled.json \
  --runs docs/verification/search-baseline-2026-10-26.json \
    docs/verification/search-variants-dataflows-2026-11-03.json \
  --assessment docs/verification/search-ai-assessment-2026-11-04.json \
  --output /tmp/ai-scores.json
.venv/bin/python scripts/evaluate_search.py judge \
  --suite /tmp/pooled.json --judge a --format csv --output /tmp/judge-a.csv
.venv/bin/python scripts/evaluate_search.py judge \
  --suite /tmp/pooled.json --judge b --format csv --output /tmp/judge-b.csv
```

Give each initially blank CSV to a different person. Edit only `grade`: blank means
unknown; `0`, `1`, `2` follow the rubric in
[SEARCH_EVALUATION.md](../SEARCH_EVALUATION.md). Keep rows and context intact,
save as comma-delimited UTF-8 CSV, and record the two people's names/dates in the
eventual research report. Do not distribute the AI file as an independent judge.

```bash
.venv/bin/python scripts/evaluate_search.py merge --suite /tmp/pooled.json \
  --judge-a /tmp/judge-a.csv --judge-b /tmp/judge-b.csv --output /tmp/judged.json
# Resolve every disagreement in judged.json with resolved: 0–2 and a reason.
.venv/bin/python scripts/evaluate_search.py score --suite /tmp/judged.json \
  --runs docs/verification/search-baseline-2026-10-26.json \
    docs/verification/search-variants-dataflows-2026-11-03.json \
  --require-complete --output /tmp/human-scores.json
```

With the unchanged blank sheets the merge succeeds, but strict human scoring
must exit **1** and report **917 judgments / 0 completed**. AI scoring remains a
separate command and never imports those grades into the human study.
