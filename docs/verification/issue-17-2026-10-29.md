# Issue #17 verification — 2026-10-29

Feature branch: `feature/17-search-backend`, built from `origin/develop` (`5aecefb`,
which includes the #16 indexer).

## Real cluster

`TUIK_OPENSEARCH_URL=http://127.0.0.1:9200 .venv/bin/pytest -m opensearch -q` against a
local single-node OpenSearch 3.3.2 (the Compose image, security disabled). The new
test builds a UUID alias from seven Turkish fixture documents with the #16 indexer:

- `issizlik` (ASCII) → `flow:DF_ISSIZ+V1.0` first, and the labour bulletin through the
  fuzzy body clause.
- `işsizliğin` (inflected) → the dataset and both labour bulletins.
- `TÜFE` and `TUFE` → only `press:1` (Tüketici Fiyat Endeksi); the Yurt İçi Üretici
  Fiyat Endeksi bulletin is not returned.
- `kinds`+`downloadable`, `themes`, `published_after` and `limit`/`total` paging filter
  as expected; title highlights contain `<em>`, and a ~180,000-character body
  highlights within the 100,000-character analysis bound.

All test indices are deleted afterwards. A pre-implementation probe on the same
cluster confirmed that `fuzziness: AUTO` combines with the synonym-graph search
analyzers without errors, that `prefix_length: 1` keeps `TÜFE`/`ÜFE` apart, and that
`enflasyon` ranks the producer price bulletin above the consumer price bulletin
(documented as a #20 relevance question).
