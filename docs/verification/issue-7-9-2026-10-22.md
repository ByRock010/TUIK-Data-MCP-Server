## Meaningful offline coverage

Both real PDF fixtures match their observed page counts and text prefixes. Tests
cover deduplicated bold glyphs, Turkish text normalization, page locators, bounded
chunks, blank pages, unreadable files, page/call/glyph limits, out-of-range pages,
multiple-file choices, response character caps, complete same-page reconstruction,
and reuse of the downloaded body/parsed page across different offsets.

Workbook tests retain the existing real goldens and additionally reject oversized
XLS/XLSX grids, excessive sheets/inflated ZIP payloads and sparse extreme row
coordinates. Falsely small XLSX dimensions do not hide data. Source errors retain
`parse_failed` / `parse_limit_exceeded` rather than caller `invalid_input`.

Cache tests cover concurrent shared download/parse, mutable result isolation,
byte-budget eviction, TTL expiry and a changed body under the same stable ID.
An expired snapshot with a new SHA-256 cannot reuse old parsed content. A worker
remains active until completion even if its caller is cancelled repeatedly.

## Limits and remaining scope

A byte-bounded cache and input budgets are not hard process-memory/CPU isolation.
PDF layout/text extraction runs only for requested pages, but parser libraries
must still decode their inputs. No OCR, PDF table reconstruction, OpenSearch
indexing, automatic file crawling or release/tag publication is included.
The tool's `no_text_layer` applies only to the requested page (which may be blank).
