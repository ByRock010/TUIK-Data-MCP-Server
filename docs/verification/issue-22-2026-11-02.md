## Review fixes (PR #66, 2026-11-03)

Both findings were reproduced as failing regression tests on `9c998d9` with the
recorded labour fixtures:

- **Failures no longer starve later files.** With two downloads per run, the
  reviewed code retried the same two unavailable files on every run and never
  reached the available `Temel işgücü göstergeleri (15+ yaş)` workbook. The state
  now records attempts per listed file; never-tried files get the budget before
  earlier failures (fewest attempts first), so run 3 indexes that workbook. Each
  failure is retried at most three times, after which a run makes no requests for
  it; a republished bulletin's fresh file list starts its files over.
- **Deferred refreshes keep cached files.** Repeating `on_demand=[PDF, BASIC]` with
  one download used to drop BASIC from the documents and the state. A deferred or
  zero-budget explicit refresh now keeps the cached entry, including its on-demand
  flag, and is reported as `pending_refreshes`.

After the fixes: `.venv/bin/pytest -q` **585 passed, 5 skipped, 6 deselected**;
`pytest -m opensearch` on the local 3.3.2 cluster **5 passed**; Ruff passed.

### Second review round (2026-11-03)

- **Failing file lists no longer starve later bulletins.** The file-list cap counted
  failed requests without remembering them, so newer bulletins whose detail kept
  failing used the whole list budget on every run. With `press:60000` and
  `press:59000` returning 404 before the recorded `press:57987` and two requests per
  run, the reviewed `32cf26e` never requested `/press/57987`. List failures are now
  kept in the state per bulletin and publication; never-fetched lists go first and a
  failing list is retried at most three times, so run 2 indexes `press:57987`'s
  files and the failing bulletins settle as `lists_given_up`. A republished bulletin
  gets a fresh attempt. Each run in the regression reloads the serialized state and
  uses a new HTTP client.

After this fix: `.venv/bin/pytest -q` **586 passed, 5 skipped, 6 deselected**;
`pytest -m opensearch` on the local 3.3.2 cluster **5 passed**; Ruff and 28 Node
tests passed.
