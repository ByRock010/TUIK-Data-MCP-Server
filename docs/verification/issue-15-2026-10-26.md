## Scope

The recorded live crawl is deliberately bounded. A full ~1,500-bulletin historical
refresh was not run, and whole-catalog theme completeness is not claimed. Complete
enumeration/checkpoint behavior is covered offline. The implementation emits only
metadata documents; bulk indexing, alias activation and search routing remain
#16–#18. This completes #15's fixture tests and dated live dry-run count/coverage
acceptance criteria with the sample scope explicitly retained.

## Review correction — 2026-10-26

Berkay correctly identified that equal raw row totals do not prove complete unique
coverage. The earlier overlap test accepted `[A, B]`, `[B]` with `total=3`, although
C could be unseen. That expectation was wrong and has been replaced.

Complete enumeration now requires both raw row count and unique bulletin count to
equal the upstream total. A mismatch raises `incomplete_listing` before fetching
details, replacing output or exposing `next_state`. Error reports retain raw/unique
counts and duplicate diagnostics. Partial previews remain explicitly ineligible
for state commits. There is no evidence-based exception for stable duplicate rows.

Eighteen crawler tests now include cold-state and previously cached C regressions,
plus a CLI regression proving old JSONL/state bytes survive the overlap failure.
Confirmed missing IDs also produce an explicit warning before downstream removals.
The local IPv4 option's proxy limitation is documented. Earlier dated live samples
remain evidence of their stated partial scope, not a full-list completeness proof.
